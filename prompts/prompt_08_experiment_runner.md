# Промпт 08. Оркестрация эксперимента и сохранение результатов

Следующий шаг — собрать все компоненты и реализовать скрипт, который запускает полный эксперимент: генерацию данных, оптимизацию топологии, сравнение с базовыми методами и сохранение результатов. Скрипт должен быть максимально простым в использовании и воспроизводимым.

## Задание

1. В каталоге `scripts/` создай файл `run_experiment.py`. В этом файле реализуй исполнение, которое выполняет следующие этапы:
   1. Загружает или инициализирует конфигурацию эксперимента (`ExperimentConfig`, `HypergraphConfig`, `OptimizationConfig`, `RetrievalConfig`) с параметрами, подходящими для основного научного эксперимента (достаточно большое число вершин, паттернов и поколений эволюции). При этом позволить переопределять эти параметры через аргументы командной строки (например, `--seed`, `--n-generations`, `--population-size`, `--n-vertices`, `--n-patterns`, `--candidate-pool-size`, `--output-dir`).
   2. Устанавливает seed для воспроизводимости.
   3. Генерирует обучающие паттерны и тесты с помощью функций из `patterns.py`.
   4. Строит пул гиперребер с учётом статистики паттернов и случайного дополнения (функция будет реализована позже). Размер пула должен соответствовать параметру конфигурации.
   5. Запускает алгоритм NSGA‑II на основе функции `run_nsga2`, получает результаты и таблицу метрик для решений на Парето‑фронте.
   6. Запускает функции из `baselines.py` для оценки базовых топологий, собирает таблицы метрик.
   7. Сохраняет результаты в папку `results/`: 
      - CSV‑файл с паттернами (`tables/patterns.csv`);
      - CSV‑файл с пулом гиперребер (`tables/candidate_pool.csv`);
      - CSV‑файл с решениями Парето‑фронта (`tables/pareto_solutions.csv`);
      - CSV‑файл с метриками для всех решений (`tables/nsga_objectives.csv`);
      - CSV‑файл с результатами базовых топологий (`tables/baseline_metrics.csv`);
      - JSON‑файл `reports/experiment_summary.json`, содержащий основные параметры эксперимента, количество решений на фронте, лучшие решения по каждому критерию и другие метаданные.

      После сохранения всех файлов **обнови файл `results/report.md`**. В отчёт нужно **последовательно добавлять** информацию по каждому выполненному эксперименту. Для этого:
      - В начале отчёта размести заголовок, который идентифицирует запуск (например, «Основной эксперимент»). Если это первый эксперимент, отчёт будет начинаться с этого заголовка.
      - Далее приложи таблицы и изображения из этого запуска. В отчёте можно вставлять ссылки на соответствующие файлы (`tables/…`, `figures/…`) или, если позволяют возможности среды, вставлять изображения напрямую. Таблицы можно привести в виде кратких сводок: количество решений, средние значения метрик и т. п.
      - Под таблицами напиши краткое описание хода эксперимента: как изменялся алгоритм в процессе эволюции (например, улучшаются ли значения метрик от поколения к поколению), какие особенности наблюдаются (например, большая плотность гиперребер ведёт к повышению точности, но снижает различение), каков характер сходимости.
      - В конце раздела по эксперименту укажи, какие гипотезы из H1–H3 подтверждаются или опровергаются на основе предварительных результатов, **без статистических деталей**.

      Важно: **не затирай** предыдущие записи в `report.md`. Каждый эксперимент должен добавляться в отчёт как новый раздел. Не вставляй в отчёт код или имена переменных; описывай результаты и реакции программы на высоком уровне.
   8. (Позже) Визуализации и статистика будут выполняться отдельным скриптом (Промпт 09).
2. Скрипт должен использовать параллельные вычисления, если это ускоряет оптимизацию (например, параметр `n_processes` в `pymoo`). Однако реализовать это нужно аккуратно, чтобы не усложнять код.
3. Убедись, что скрипт может быть запущен командой:
   ```
   python scripts/run_experiment.py
   ```
   и при желании с аргументами, изменяющими параметры.
4. Не добавляй в скрипт интерфейсов пользователя, графических элементов или лишнего логирования. Комментарии должны быть на русском языке.

```

2. Какие файлы созданы или изменены:
   - …
3. Как запустить проверку:
   - … (например, указать команду и описать, что должно быть создано в результате)
4. Результат проверки:
   - …
5. Возможные проблемы:
   - …
6. Что нужно уточнить перед следующим шагом:
   - …
7. Отклонения от промпта:
   - …
```

Опиши в отчёте, какие файлы сохраняются и какую информацию они содержат, не переходя к техническим деталям реализации. Это поможет при написании статьи.
