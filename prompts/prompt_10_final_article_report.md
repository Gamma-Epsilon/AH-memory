# Промпт 10. Завершение отчёта и финальный обзор

Заключительный этап заключается в финализации отчёта о результатах эксперимента, который суммирует полученные данные и статусы гипотез. Напоминаем: отчёт предназначен для внутреннего использования пользователем и ассистентом и не является готовой статьёй для журнала. В отчёте не должно быть научного стиля, литературного обзора, ссылок на статьи или кода.

## Задание

1. Открой файл `results/report.md`, созданный на первом этапе, и добавь в него итоговый раздел. Этот раздел должен объединить все сведения о параметрах эксперимента, основных метриках, проверках гипотез и созданных файлах. **Не удаляй** предыдущие записи: твоя задача — завершить отчёт, подведя итоги.

2. В последнем разделе отчёта перечисли:
   - **Параметры эксперимента.** Перечисли значимые параметры: число вершин и паттернов, параметры генерации (доля единиц, число кластеров, расстояния), размеры пула гиперребер, параметры NSGA‑II (размер популяции, число поколений, вероятность кроссовера и мутации) и предельные размеры топологии. Можно сформулировать это в виде списка или краткого описания.
   - **Результаты метрик.** Сводные результаты основных функциональных и структурных метрик для лучших топологий и базовых стратегий. Укажи средние значения точности восстановления, устойчивости, различения и показатели структуры (число гиперребер, средняя кратность, плотность). Приведи примеры наилучших значений.
   - **Проверка гипотез.** Укажи, подтверждена или опровергнута каждая из гипотез H1–H3 на основе статистического анализа. Напиши краткое пояснение для каждой гипотезы без статистических подробностей.
   - **Ссылки на файлы.** Перечисли все созданные файлы (CSV, PNG, TXT, JSON и т. д.) с кратким описанием их содержания. Это поможет при дальнейшей работе над статьёй.
   - **Краткие выводы.** Дай несколько предложений, суммирующих основные наблюдения: какие топологии показали лучшие характеристики, какова зависимость между сложностью и качеством, какие параметры оказались наиболее важными.

3. Сохрани обновлённый отчёт в том же файле `results/report.md`. Не используй новую версию файла: отчёт должен быть единым документом, пополняемым по мере выполнения экспериментов.

4. Обнови файл `results/reports/experiment_summary.json`, добавив в него ссылку на `report.md` и отметив, что итоговый отчёт составлен.

> **Важно.** Codex не должен писать полноценную статью или искать научные статьи в интернете. Итоговый отчёт должен формироваться только на основе полученных данных и метрик. Финальную статью будет писать пользователь (и ассистент) отдельно, используя этот отчёт.

## Формат отчёта

По завершении подготовь отчёт:

```
ОТЧЁТ ПО ПРОМПТУ №10

1. Что сделано:
   - … (укажи, что добавлен финальный раздел в report.md и обновлён experiment_summary.json)
2. Какие файлы созданы или изменены:
   - … (например, results/report.md, results/reports/experiment_summary.json)
3. Как запустить проверку:
   - … (коротко опиши, как проверить, что отчёт заполнен и содержит итоговые данные)
4. Результат проверки:
   - …
5. Возможные проблемы:
   - …
6. Что нужно уточнить перед следующим шагом:
   - …
7. Отклонения от промпта:
   - …
```

В отчёте по этому промпту не нужно пересказывать содержание отчёта в `report.md`; достаточно указать, что финальный раздел добавлен. Основной текст будет храниться в самом `report.md`.
