# Промпт 09. Визуализация результатов и статистический анализ

После выполнения оптимизации и получения таблиц метрик необходимо построить графики и провести статистический анализ, чтобы обосновать выводы для статьи. Этот этап разделён на две части: визуализация Парето‑фронта и сравнений, а также проверка гипотез H1–H3.

## Задание

1. **Визуализация.** В модуле `src/ah_memory/visualization.py` реализуй функции для создания следующих графиков (используй `matplotlib`, без `seaborn`):
   - **График «точность–сложность» для Парето‑фронта.** По оси X — структурная сложность (функция f4), по оси Y — точность восстановления. Точки, соответствующие решениям NSGA‑II, должны быть нанесены на график. Сохраняй файл как `results/figures/pareto_accuracy_complexity.png`.
   - **График «устойчивость–различение».** По оси X — устойчивость к шуму, по оси Y — способность различать близкие паттерны. Сохраняй как `results/figures/pareto_robustness_discrimination.png`.
   - **Сравнение с базовыми топологиями.** Построй, например, диаграмму размаха (boxplot) или точки по трём метрикам: точность восстановления, устойчивость и различение, сравнивая NSGA‑II с каждой базовой топологией. Сохраняй как `results/figures/baseline_comparison_boxplot.png`.
   - **Распределение степеней и размеров гиперребер.** Для лучшего решения по точности построй гистограмму степеней вершин (`degree_distribution_best_accuracy.png`) и гистограмму размеров гиперребер (`hyperedge_size_histogram_best_accuracy.png`). Это позволит проанализировать структуру топологии.
   - **Кривые зависимости точности от уровня шума.** Построй графики точности для лучшей топологии и для каждой базовой топологии при разных уровнях шума. Сохраняй как `results/figures/noise_curve_best_vs_baselines.png`.
2. **Статистический анализ.** В модуле `src/ah_memory/statistics.py` реализуй функции для проверки гипотез:
   - `compare_nsga_vs_random(nsga_df, random_df)`: сравнение средних показателей между решениями NSGA‑II и случайными топологиями по метрикам точности, устойчивости и различения. Используй непараметрические тесты (например, Манна–Уитни) и вычисляй размеры эффекта (например, Cliff’s Delta). Результаты должны быть сохранены в `results/reports/hypothesis_tests.csv`.
   - `analyze_structural_ranges(pareto_df)`: поиск характерных диапазонов средних размеров гиперребер, плотности и числа гиперребер для лучших 25 % решений по качеству. Возвращай таблицу диапазонов и сохрани её в `results/reports/hypothesis_ranges.csv`.
   - `test_hypotheses(nsga_df, baseline_df)`: проверка трёх гипотез (H1–H3) на основе проведённых тестов. Сохрани текстовый отчёт с выводами в `results/reports/hypothesis_summary.txt`.
3. Расширь скрипт `run_experiment.py` или создай отдельный скрипт (например, `scripts/post_analysis.py`), который после завершения оптимизации и получения метрик:
   - вызывает функции визуализации, формируя все графики;
   - вызывает функции статистического анализа и сохраняет результаты в указанные файлы;
   - обновляет файл `reports/experiment_summary.json`, добавляя ссылки на созданные рисунки и файлы с результатами статистики.

   После генерации графиков и выполнения статистического анализа **обнови общий отчёт `results/report.md`**. В отдельном разделе, посвящённом визуализации и статистике:
    - Вставь ссылки на созданные изображения (например, `figures/pareto_accuracy_complexity.png`, `figures/pareto_robustness_discrimination.png` и т. д.).
    - Сформулируй краткие выводы по каждому графику: что отражает каждой из осей, какие тенденции видны, как распределены решения NSGA‑II относительно базовых топологий.
    - Укажи, какие гипотезы подтверждаются или опровергаются по результатам статистических тестов, не приводя числовые p‑значения.
    - При необходимости добавь краткое описание того, как статистический анализ помогает понять структуру топологий (например, характерные диапазоны средней кратности и плотности для лучших решений).

   Этот отчёт должен оставаться компактным: перечисляй только факты и наблюдения, без упоминания кода, названий переменных или внешних источников. Новые сведения должны дополнять отчёт, не заменяя предыдущие разделы.
4. Комментируй функции и скрипты на русском языке. Следи, чтобы код оставался понятным и без лишних абстракций.
